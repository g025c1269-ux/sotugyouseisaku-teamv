# 観察モード：解説方式と年1回の総括

## 基準と変更範囲

最新main `6b5d0253479dcaaaf6586226ce5efea723bff98b` から作成した `feature/annual-explanation-sync` で作業しています。mainへの直接pushは行いません。

mainには前回の方式選択統合が未反映のため、既存の `integration/explanation-mode` の `af229f3` を前提として再利用しました。前提コミットと今回の年間更新コミットを分けてレビューできます。前回の設定画面・開始/ロード接続には追加修正を加えていません。

通常の個体解説はmainの最新版を維持します。AIは `feature/ollama-navigator` のコードと履歴（`85ea0a4`、既存AI本体の `7ae7417`）を確認して再利用しています。今回は年間記録を両方式で共有し、全体解説を年末更新に揃えます。個体解説、AIプロンプト・モデル名・接続先は変更していません。

## 1年と更新の判定

既存の `season_effects.year_of(generation)` と `config.SEASON_CYCLE` が春夏秋冬の1周期を表し、現在は12世代で1年です。新しい時間設定や「1世代＝1年」という換算は追加しません。

両方式で `AnnualHistory.advance` → `AnnualRecorder` を使います。実際の各ステップの前後で観測し、周期最後の世代が完了したときだけ `year_completed=true` を確定します。再描画、ステータス変化、停止/再開では文章を作り直しません。高速時や1世代送りでも、既存の各ステップへの接続で年末を検出します。

年番号で記録を管理し、同じ年を再訪しても最初に記録した総括を再生成しません。年途中からロードした場合は、次の年末に観察できた範囲だけをまとめ、途中からの記録と表示します。年途中で計算完了・絶滅した場合はデータだけを `incomplete` として保存し、表示更新やAI送信は行いません。最後の月の途中で絶滅した場合も完全な1年とは扱いません。

## 年間データと文章

両種の年初/年末個体数と増減、平均形質と差、年末の3段階分布を記録します。環境は実際に観測した気温の開始/終了・差・最小/最大と食物数の差です。災害/環境イベントは取得機能がないため `events=null` とし、出来事や因果関係を補完しません。

通常解説はPythonの条件分岐だけで、各種の数の増減、注目する平均形質の変化（既存と同じ差0.05以上）、気温や食物の観測差を短く紹介します。比較不能な平均はその旨を伝え、現在の行動方式で使わない形質は解説候補から除外します。平均の変化を個体の行動や増減の原因とは断定しません。

AIは同じ年の確定データをコピーして順番に処理します。既存の同時1リクエスト、別スレッド、タイムアウト、失敗時のルール総括を維持します。通常解説はAIコントローラーを生成せず、Ollamaへ接続しません。

## 表示と選択

- 通常：既存3吹き出しの上2枚に、草食・肉食の年間変化を表示します。見出しは「○年目の総括」、数値は開始→終了の個体数です。
- AI：既存の年間総括/選択個体タブと履歴を維持します。「観察」の両種カードも、最後に完成した総括と同じ年のデータを使います。
- 両方式：初回は「最初の1年間を観察中！」。次の総括が完成するまで前回文を保持します。AI待機中に翌年の文章や数値へ先行して切り替えません。
- 個体カード・Tab詳細は従来どおり現在の選択個体を確認できます。個体AIも手動更新のままです。

アイコン・吹き出し・折り返しの描画関数と位置は変更していません。年間履歴は実行中と `reports/annual_*.json` に保持し、セーブ形式には追加しません。

前回統合の設定画面もそのままです。通常解説が既定で、AI選択時だけ導入案内と非同期の利用可否チェックを表示します。接続先 `http://localhost:11434`、モデル `qwen3:4b`、`think=false` を維持します。未準備なら通常解説へ戻して開始できます。選択は開始/ロードの両方へ渡します。
