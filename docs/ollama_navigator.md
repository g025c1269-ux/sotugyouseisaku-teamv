# OllamaローカルAIナビ

## 調査した基準と実装範囲

最新 `origin/main` **b44e462dbbcddcadb40d06409e73194ccb2ff956** から `feature/ollama-navigator` を作成しました。季節別食料倍率・気温の位相・最新描画・起動時に解説を閉じる動作を維持しています。過去ブランチの生態系コードは使っていません。

個体数は `world.organisms` の `alive` と `org_type` から取得します。個体は `main.py` の `selected_org`、遺伝子は `org.genes`、エネルギーは `energy/max_energy`、年齢は `age` です。平均・分布は既存 `NavigatorExplainer.population` を再利用します。気温はシミュレーションが更新した `config.TEMPERATURE` を読み、ナビ側から更新しません。NN重み・行動履歴・マップ全体はAIへ送りません。

## 閾値と意味

全遺伝子の値域は0〜1です。突然変異後もこの範囲に制限されます。分類は既存 `data/status_explanations.json` と `StatusExplainer.classify` を共有します。

| 項目 | LOW | MID | HIGH | 実際の意味 |
| --- | --- | --- | --- | --- |
| 温度適性 `cold_resistance` | <1/3 | ≥1/3かつ<2/3 | ≥2/3 | 気温/40との差×種別係数が消費。砂漠では1.3倍。高いほど寒さに強いとは限らない |
| 速度 `speed` | <0.4 | ≥0.4かつ<0.6 | ≥0.6 | 値は2マス移動の確率。2マス移動時は消費も2回 |
| 繁殖の重み `hunger_threshold` | <0.4 | ≥0.4かつ<0.6 | ≥0.6 | ルール方式の繁殖スコア。現在のNN方式では未使用 |
| 代謝 `metabolism` | <0.4 | ≥0.4かつ<0.6 | ≥0.6 | 容量と基本消費の両方に0.5+値を掛ける |
| 川適応 `river_tolerance` | <0.4 | ≥0.4かつ<0.8 | ≥0.8 | 川の移動消費倍率3−2×値 |
| 山適応 `mountain_tolerance` | <1/3 | ≥1/3かつ<2/3 | ≥2/3 | 山の移動消費倍率2−値 |
| エネルギー充足率 | <0.4 | ≥0.4かつ<0.8 | ≥0.8 | 蓄え/容量。80%以上は繁殖の必要条件の一つ |

各種平均の高低は**平均値に同じ閾値を適用した評価**であり、個体のLOW/MID/HIGH分布も別に送ります。温度消費は平均遺伝子からの推定ではなく、現在地の砂漠補正を含む各個体の既存読取専用メソッド `_calc_temp_penalty` の平均です。移動消費も `_move_energy_cost` を読みます。

選択個体については全6遺伝子を同種の生存個体の平均（選択個体自身も含む）と比較します。差が+0.05以上は「高め」、−0.05以下は「低め」、その間は「同じくらい」です。0.05は表示上の目安で、生態系パラメータではありません。高め＝必ず長所とはせず、意味とトレードオフを併記します。

## 通信と表示

公式の `POST http://localhost:11434/api/chat` を標準ライブラリ `urllib` で呼び出します。モデルは `qwen3:4b`、`think=false`、`stream=false`。JSON形式の `comment` 一つだけを受け取り、日本語を含む40〜80文字であることを検証します。不正・長過ぎ・短過ぎ・途中終了の応答は表示せずルール解説に戻します。出力上限256トークン、コンテキスト4096トークン、CPUスレッド数4、モデルの常駐は最終要求後2分が初期値です。

接続先・モデル・時間制限などは `data/ollama_config.json` で変更でき、次の手動更新時に読み込みます。接続先はローカルのlocalhost/ループバックIPのみ受け付けます。HTTPプロキシは使わず、リダイレクトも追跡しません。クラウドサービス、APIキー、OllamaのPythonライブラリは不要です。

初期設定は通信タイムアウト60秒、同時リクエスト1件です。ワーカースレッドはPygameやWorldを扱わず、メインスレッドで作った数値・分類・説明のコピーだけを受け取ります。結果はキュー経由でメインスレッドの吹き出しへ渡します。起動・毎フレーム・毎世代・対象切替での自動送信はしません。エラー時の自動再試行もありません。

「考え中...」の間は現在のルール解説を残し、操作を続けられます。成功したAI文には**更新時の世代・累計ステップ**を表示します。シミュレーションは進むため、AI文は現在値へ自動追従しません。最新値は「観察」→「詳細」で確認できます。

対象タブごとに結果を管理し、別種の文を混ぜません。個体の変更・死亡・リストからの削除で個体の結果を消し、実行中の古い返事も破棄します。一度別個体へ変えて戻した場合も再更新が必要です。巻き戻し等でWorldが置換された場合は全結果を破棄します。絶滅中の集団には過去の生存集団のAI文を表示しません。処理中に閉じても終了を待たず、Ollamaの接続設定が壊れていてもゲーム自体は起動できます。

AI文は参考コメントです。根拠をPythonで整理してプロンプトへ渡し、情報の創作や未来の断定をしないよう指定していますが、自然文の内容の正しさを完全に機械判定するものではありません。実モデルの文章の適切さは実機テストで確認してください。AI文を実行・評価したり、計算パラメータへ戻す処理はありません。

作業ブランチのZIPをすべて展開し、READMEのPython 3.12の手順で依存をインストールしてください。

```powershell
ollama list
# qwen3:4b が一覧にあることを確認。Ollamaアプリを起動しておく。
.\.venv\Scripts\python.exe verify_ollama.py
.\.venv\Scripts\python.exe main.py
```

`verify_ollama.py` は3対象を順に実モデルへ送り、返事と文字数を表示します。失敗時は日本語の案内と終了コード1を返します。`--target individual` で1対象だけ、`--context-only` で通信せず入力データだけ確認できます。保存データは変更せず、確認用の独立した初期ワールドを使います。

ゲームでは次を確認してください。

1. タイトル→神様モード→N/「解説」→AI。「草食全体」を更新して日本語40〜80文字の解説が出る。
2. 「肉食全体」も更新できる。個体未選択でも両種の全体解説を使える。
3. マップ上の個体を選択し「選択個体」を更新。集団との比較や長所・注意点を含む文章になっている。
4. 「考え中...」中にSpace・WASD・ズーム・V/E・Nを操作できる。同時更新はできない。
5. 生成中に別の個体を選び、古い個体の返事が出ない。世代を巻き戻した場合も古い返事が出ない。
6. Ollamaを終了した状態で起動・更新してもゲームが終了せず、案内とルール解説が出る。
7. AI生成中でもEsc/ウィンドウを閉じる操作で終了できる。

Ryzen 5 8640U・16GB・Radeon 760Mでの実速度・使用メモリ・GPU利用は未測定です。スレッド数4と小さめのコンテキストを初期値にしていますが、GPU利用はOllamaの対応状況に依存します。初回のモデルロードで時間切れになる場合は、Ollama側の動作を確認したうえで `timeout_seconds` を120など（最大180秒）へ変更してください。`ollama serve` はOllamaアプリがサーバーを起動していない場合だけ必要です。

2026-10-27、Python 3.12 / Linux / SDL offscreenで **47テストすべて成功**。APIの送信先・モデル・think=false・文字数制限、3対象、接続拒否・時間切れ・モデル不在・不正応答・設定不良、単一リクエスト、選択変更・死亡・World置換時の結果破棄、実際のmain.pyでの生成待ち中の操作と終了を確認しました。既存の全8,748件のルール解説・世代進行/巻き戻しも含みます。同じ乱数シードの12ステップを比較し、AI用データの読み取り有無で個体状態・遺伝子・脳の重み・食料・乱数状態が一致しました。

画面の確認用PNGは [screenshotsフォルダー](../screenshots/README.md) にあります。AI文は通信モックの固定文です。Windows実機、実モデルの日本語の品質、実際の生成時間・メモリ・GPU使用は未検証です。
