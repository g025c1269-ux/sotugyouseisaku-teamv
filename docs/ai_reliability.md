# AI年間総括の安定化と実機診断

> 個体解説削除前の改修記録です。現在の通常/AIナビは全体解説のみです。クリック選択と数値確認は維持しています。現在の操作は[観察ナビ](navigator.md)を参照してください。

作業ブランチは `fix/ai-annual-reliability`。最新main `6b5d025` を起点に、未マージの解説方式選択と年1回更新を前提コミットとして引き継ぎ、その上に今回の修正を分けています。

## 変更

- 年間総括は160〜190文字・5〜6文を目安にします。JSON Schemaと受信側の許容範囲は40〜2000文字です。多少の長短で破棄せず、切り詰めません。空文・極端な短文/巨大な文・日本語なし・両種への言及なしなどは不採用です。個体解説の40〜80文字制限は維持します。
- commentだけを持つJSONを検証します。全体を囲むJSONコードフェンス、文字列の外側にある末尾カンマだけ補正します。重複キー、余分なキー、欠落、任意の前後説明、Python辞書構文は受け付けません。evalは使いません。
- 年間吹き出しは長い回答をホイールでスクロールできます。アイコン/吹き出しの形・位置は維持します。
- AI生成中、AI生成成功、通常解説への代替、タイムアウト、回答形式エラーを明示します。前回の回答を表示しながら次の年を生成する動作は維持します。
- think=false、qwen3:4b、localhost:11434、年末の生成タイミング、同時1件と年単位の重複防止、通常解説の文章は維持します。自動再送は追加しません。

## 時間とログ

`data/ollama_config.json` の `timeout_seconds` は既定60秒のままです。実機計測に応じて90、120などに変更できます（対応範囲1〜180秒）。通信の待ち時間設定であり、厳密な総経過時間のタイマーではありません。値を増やしただけで改善を確認したとは扱いません。

年間履歴JSONの各レポートに `diagnostics` と `error_kind` を追加します。既存のcontext/text/fallback/status/requestを維持し、古いレポートの表示も新項目なしで動作します。

同じフォルダーの `annual_*.debug.jsonl` に、各通信試行の診断情報を1行ずつ記録します。

- year / target / model
- started_at / finished_at（UTC）
- elapsed_seconds（単調時計による計測、通信処理等の時間。年の順番待ち時間を含まない）
- timeout_seconds / success / error_kind
- characters / repairs（取得できた場合）
- ollama: total_duration / load_duration / prompt_eval_duration / eval_duration / prompt_eval_count / eval_count（応答にあれば）

Ollamaのdurationはナノ秒です。秒への換算は1,000,000,000で割ります。タイムアウト時は最終応答を得られないため、Ollama側の時間情報を取得できない場合があります。デバッグJSONLにはプロンプト・回答全文・個体データ・ユーザー名などを記録しません。既存の年間履歴JSONには従来どおりゲームの観察入力と回答が入ります。

ログ保存が失敗しても生成成功を失敗へ変えません。履歴に反映する前にゲームを終了した場合でも、ワーカーが完了できればJSONLへ記録できますが、プロセス終了で中断された通信の完了ログは保証できません。タイムアウト後の回答回収やサーバー側の明示キャンセルは追加していません。

## Windowsでの確認

1. 作業ブランチのZIPを新しいフォルダーに展開し、READMEの手順で起動します。
2. Ollamaを起動し、`ollama list` にqwen3:4bがあることを確認します。観察設定でAIを選択します。
3. 最初はtimeout_seconds=60のまま、年末まで進めます。既存のM→右矢印で12世代を進めても確認できます。
4. 「AI生成成功 · AI総括」と回答を確認します。長文は吹き出し内でホイール操作します。生成中の操作、次年の生成中に前回文が残ることも確認します。
5. reportsの最新debug.jsonlでelapsed_seconds、success、error_kindを確認します。成功した場合はload_durationとeval_duration等も比較します。
6. 初回読み込みや生成に時間が必要なら設定ファイルを90〜120秒へ変更し、再起動して比較します。タイムアウトが増え続ける場合はOllamaのログ・メモリ使用・他の生成処理も確認します。
7. Ollamaを停止する試験では「通常解説への切り替え」とconnection_errorを確認します。設定画面の利用可否確認があるので、ゲーム開始後に停止して次の年末を確認してください。
8. 通常解説で起動して従来の文章と操作が維持されることを確認します。

クラウドでの検証はモックとローカル代役HTTPです。Windows実機、実際のQwenの生成速度・品質やGPU利用は未確認です。
