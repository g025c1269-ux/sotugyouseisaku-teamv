## 調査で確認できた原因

mainの年間userデータには、年次比較のほかに全形質の分布・季節ごとの観測と、末尾の長いinterpretationが含まれていました。interpretationの「代謝は容量と基本消費の両方を増す」「速度は2マス移動の確率」「環境と増減の因果は未検証」は、報告された悪い回答とほぼ同じです。AIがどの箇所へ注目したかは実機の内部状態を見ない限り断定できませんが、回答に転用しやすい説明文を大量に渡していました。

JSON検査は形式・文字数・両種への言及を検査するもので、観測の考察とマニュアルの列挙は区別していませんでした。前回の専用ブランチで作った命令復唱の検出も再利用し、今回は明確な仕様読み上げの検出を加えています。

リポジトリのai_model/ModelfileはFROM qwen3:1.7bで、人格・公式ルール・考察手順を持ちます。ユーザーPCに作成済みのecosystem-leafと同じ内容とは仮定していません。導入済みモデルは `ollama show ecosystem-leaf:latest --modelfile` で確認してください。このクラウドにOllama実行ファイルはなく、実機のモデル定義・回答品質は未確認です。

## 実際の送信構造

- 接続：従来のlocalhost:11434/api/chat。モデルは設定ファイルのecosystem-leaf:latest、待機120秒、think=false。
- 年間：ゲーム側からsystemメッセージを送らず、モデルのSYSTEMを置き換える指定を避けます。通常のOllamaのモデル共通設定を活かす意図ですが、ローカル独自TEMPLATEの挙動は未検証です。
- 年間のuserは1件で、短いANNUAL_PROMPT＋区切り＋年次JSONです。人格と必要な参考ルールをこの入力にも含め、別モデルやSYSTEMのないモデルにも過度に依存しない構成です。
- 個体：従来のSYSTEM_PROMPT＋user JSONのままです。個体の文章・送信内容・検証条件は変更しません。
- 出力：従来どおりcommentだけのJSON Schema。目安は200〜350文字、受信の安全上限/下限40〜2000文字と軽微なJSON補正は維持し、文章を切り詰めません。
- 自動送信は年末1回、既存のキュー・タイムアウト・時間計測・履歴・診断ログを維持。追加のAPI照会や自動再試行は行いません。

## 年間AIへ渡す情報

annual_ai_context.pyは、既存の確定した記録を読み取り専用で整理します。通常解説や年間レコーダーには接続せず、AIへの送信時だけ使います。

| 項目 | 内容 |
| --- | --- |
| populations | 草食/肉食の開始・終了・差・増減率。不明はnull、ゼロと区別 |
| notable_traits | 行動に使う形質の差0.05以上から、大きい順に最大2件。開始・終了・差・形質名 |
| food_cells | 食物のあるマス数の開始・終了・差。年内の摂食量や餓死数ではない |
| temperature_c | 気温の開始・終了・差・観測最小/最大 |
| temperature_fit | 各種の平均適温=平均遺伝子値×40と気温の差。平均個体の目安で、実際の消費の平均ではない |
| zero_at_end | 年末0匹の種。年末の平均形質を0で捏造しない |
| reference_for_observed_changes | 変化した形質・気温に関係する少数のルールと食物連鎖の参考情報 |
| limits | 死因・実際の捕食成功数・通った地形は不明、平均の変化は生存選択の証明ではないこと等 |

元のinterpretation・全形質の分布・長い季節サンプル一覧は送信しません。完全な元データは従来の履歴に残り、requestには整理後の実際の入力が保存されます。参考ルールはorganism.pyの基本消費/容量、温度消費、地形移動消費、摂食/捕食処理を確認した範囲に限定しました。出生/死亡や行動の履歴を作りません。

代表的な食物減少ケースでは、system+userの合計が4,533文字から1,493文字へ減りました。文字数の比較であり、モデルのトークン数や応答速度を測ったものではありません。

## 回答の検証

命令文・出力方法の説明はinstruction_echo、複数の明確な仕様定義だけで観測の変化に触れない文はrule_recitalとして不採用にし、既存の通常解説へ代替します。どちらも診断ログへsuccess=falseとerror_kindを残します。

語尾「ください」、能力名、仮説の単語だけで拒否しません。観測した変化にルールを当てはめる正常例や、記録が不足することを正直に伝える文は採用します。これは保守的なパターン検査で、全文の意味・因果・未来予想の正しさを自動証明する仕組みではありません。全ての言い換えを検出できることや、誤検知ゼロも保証しません。

## 検証用の回答例

以下は入力ケースに合わせて人が用意した例です。実際のAI出力ではなく、実行時のプロンプトにも含めません。毎年の文章として使い回すコードはありません。

### 食物減少・草食代謝低下

入力：草食100→60、肉食20→18。herbivoreの代謝0.6→0.4。

今年は草食が100匹から60匹、肉食も20匹から18匹に減っちゃったね。食べ物のあるマスも減り、エネルギーを確保しにくかったのかもしれないよ。草食の平均代謝は0.6から0.4へ下がっていて、消費を抑えやすい方向だね！燃費のいい個体が残った可能性もあるけど、繁殖や遺伝、集団の入れ替わりでも平均は変わるよ。もし草食の減少が続けば、肉食も獲物探しに苦労するかも。来年は食べ物と両方の群れの数を一緒に追いかけてみよう！

### 気温低下・温度適性変化

入力：草食100→90、肉食20→19。herbivoreの温度適性遺伝子（旧称：耐寒性）0.5→0.2 / carnivoreの温度適性遺伝子（旧称：耐寒性）0.5→0.3。

気温が20℃から8℃へ下がり、草食の平均温度適性も0.5から0.2へ動いたね。平均の適温と気温の差は小さいままで、寒くなる中でも温度による消費の増加を抑えたのかもしれないよ！ただし、これは平均同士の比較で、一匹ずつの消耗を測った結果ではないんだ。草食も肉食も少し減っているけれど、寒さだけが理由とはまだ言えないね。この先さらに冷えるなら、肉食の温度適性も合わせて、数と気温の動きを一緒に見比べていきたいな！

### 両種の個体数減少

入力：草食100→60、肉食20→10。

草食が100匹から60匹、肉食も20匹から10匹へ減ったね。草食は肉食にとって獲物だから、草食が減って蓄えを得にくくなったことが肉食の減少にも関係したのかもしれないよ。ただ、実際に何匹を捕食したかや死亡理由の記録はないし、肉食には魚を捕る道もあるんだ。だから、餌不足だけが原因とはまだ決められないね。このまま両方の群れが減るなら、来年も草食の数と肉食の変化を一緒に追うと、つながりが少し見えてくるかもしれないね！

### 肉食の山適応上昇

入力：草食100→100、肉食20→22。carnivoreの山適応0.3→0.8。

肉食の平均山適応が0.3から0.8へ上がって、仲間も20匹から22匹に増えたね！山を通る場面では移動の消費を抑えやすくなったことが、蓄えの確保に関係したのかもしれないよ。でも、どの地形を通ったかは記録されていないから、山適応が増加の決め手だったとは言えないんだ。草食チームは100匹を保っているね！もし山をよく使う環境なら、この適応が肉食の暮らしにどう響くか、来年の数の変化と合わせて見ていきたいな！

### 川適応低下

入力：草食100→95、肉食20→19。herbivoreの川適応0.8→0.3。

草食の平均川適応が0.8から0.3へ下がり、数も100匹から95匹へ少し減ったね。川を渡る場面なら消費が増える方向だから、蓄えに余裕がなくなった可能性はありそうだよ。ただ、実際に川を通った記録はないので、川適応の低下が減少の原因とはまだ言えないね。肉食も20匹から19匹になったけれど、捕食の回数は不明なんだ。この傾向が続くなら、来年も両方の数と川適応を比べて、変化のつながりをこれからも一緒に探してみよう！

### 個体数ほぼ不変

入力：草食100→101、肉食20→20。

草食は100匹から101匹、肉食は20匹のままで、今年はほぼ数を保ったね！食べ物のあるマス数も年初と年末で変わっていないよ。食べることと消費の釣り合いが保たれたのかもしれないけれど、年内の摂食や誕生、死亡の回数は分からないんだ。だから、変化が少なく見えても、ずっと同じ暮らしだったとは限らないね。もし食べ物や気温が変われば両方の群れの関係も動くかも。来年も安定が続くか、ここが生態系の面白いところだね！

### 両種0匹

入力：草食100→0、肉食20→0。

年初にいた草食100匹と肉食20匹は、年末にはどちらも0匹になったね。草食が減ると獲物を得にくくなることが、肉食の減少にも関係したのかもしれないよ。ただし捕食や死亡の記録はなく、どちらが先に減ったかも、この年初と年末の比較だけでは分からないんだ。平均形質も年末は比べられないから、能力がゼロになったという話ではないよ。繁殖する親も残っていないので、このまま自然に群れが復活するとは期待できないね。この記録は大事に残しておこう。
