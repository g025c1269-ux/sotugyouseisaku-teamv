# 生物のステータス組み合わせ解説

## 使用方法

`python main.py` で起動し、盤面の生物をクリックすると右側に解説が表示されます。
右側のパネル上でホイールを動かすと全文を読めます。「閉じる」または E キーで元の詳細表示に戻り、E キーで再表示します。
別の個体を選択すると、その個体の解説を先頭から表示します。空白のクリックによる選択解除、ズーム、追跡、速度調整、Space、M、世代の送り戻し、Esc は既存の処理を使用します。
右側パネルを表示中は、その領域へのクリック・ホイールだけを解説用に使います。速度スライダーを操作するときは解説を閉じてください。解説を開いても時間は停止しません。

## 調査したステータスと値域

両種とも `Organism.genes` に次の6種類を持ちます。

| キー | 表示・意味 | 初期値域 | 生存中の使用箇所 |
| --- | --- | --- | --- |
| cold_resistance | 温度適性遺伝子（既存名は耐寒性） | 0〜1 | 気温 / 40 との差による消費 |
| speed | 移動速度 | 0.2〜0.8 | 2マス移動になる確率 |
| hunger_threshold | 繁殖行動の重み | 0.3〜0.7 | 繁殖の行動スコア |
| metabolism | 代謝 | 0〜1 | 基本消費とエネルギー容量 |
| river_tolerance | 川適応 | 0〜1 | 川の移動倍率、肉食のみ捕魚確率 |
| mountain_tolerance | 山適応 | 0〜1 | 山の移動倍率 |

突然変異後は **全遺伝子が0〜1にクリップ**されるため、初期範囲の狭い速度・繁殖の重みも0〜1を分類対象とします。遺伝子値は高いほど有利とは限りません。

`hunger_threshold` は名前から空腹時の判断閾値と解釈せず、実装どおり繁殖行動の重みとして説明します。エネルギー率が80%以上のときだけ繁殖候補が作られます。草食の繁殖スコアは `エネルギー率 × hunger_threshold`、肉食ではさらに `0.3 + 0.7 × min(近隣草食数 / 8, 1)` が掛かります。ランダム移動のスコアは0.4です。繁殖用パラメータ名 `*_REPRODUCTION_ENERGY` は現在の行動選択では使われず、解説にも使用しません。

年齢（age、経過ステップ）、エネルギー（energy）、最大エネルギー（max_energy）、座標（x/y）、生存フラグ（alive）も実在します。エネルギーは最大値に対する充足率として3段階に分類します。最大エネルギーは代謝から決まる従属値なので、代謝と独立の組み合わせ軸にはしません。年齢に寿命・老化・成熟の計算はなく、座標と生存フラグも能力の大小ではないため、事実として表示し3段階の能力評価は作りません。

現在の最大エネルギーは草食 `100 × (0.5 + metabolism)`（50〜150）、肉食 `120 × (0.5 + metabolism)`（60〜180）です。実画面では個体が保持する値をそのまま表示します。負のエネルギーは死亡ステップで生じ得るため、充足率の評価だけ0に丸め、元の値は変更しません。

## 閾値

すべて **LOW: 0 ≤ 値 < 下限、MID: 下限 ≤ 値 < 上限、HIGH: 上限 ≤ 値 ≤ 1** です。表示上の丸めた値ではなく、生の値で判定します。

| ステータス | MIDの下限 | HIGHの下限 | 理由 |
| --- | --- | --- | --- |
| 温度適性遺伝子 | 1/3 | 2/3 | 0〜1の等分。適合中心は値×40℃ |
| 移動速度 | 0.4 | 0.6 | 初期0.2〜0.8を3分割。変異後0〜1にも対応 |
| 繁殖行動の重み | 0.4 | 0.6 | ランダム移動スコア0.4との比較を考慮。0.4未満では繁殖スコアが0.4を下回る |
| 代謝 | 1/3 | 2/3 | 消費と容量を共に変える連続値を等分 |
| 川適応 | 0.4 | 0.8 | 川移動倍率が2.2倍・1.4倍となる区切りと捕魚条件0.8を考慮 |
| 山適応 | 1/3 | 2/3 | 1〜2倍の連続移動コストを等分 |
| エネルギー充足率 | 0.4 | 0.8 | LOWは補給上の注意目安。0.8は実際の繁殖候補条件 |

分類は解説用であり、新しい行動条件ではありません。川適応0.8はHIGHですが、肉食の捕魚確率 `(river_tolerance - 0.8) × 5 × 0.5` は0です。0.8を超えた場合に限り、川で正の確率になります。草食には捕魚の説明をしません。

### 「耐寒性」という名称について

現コードの気温消費は `abs(気温 / 40 - cold_resistance) × 種ごとの係数`（砂漠ではさらに倍率）です。**高い値が寒さに強いという計算ではありません**。例えば値0.1は4℃、0.9は36℃で気温消費が最小になります。解説画面では温度適性として表し、現在地・現在気温の正確な消費も表示します。既存の遺伝子名や他担当の描画は変更していません。

速度は2マス移動の確率であり、攻撃力・回避率・視野を変えません。2マス移動時には移動消費も2回分になります。代謝の高さも繁殖成功率を直接上げるわけではなく、基本消費・容量の両方を大きくします。川と山の適応は地形の移動消費を変え、地形自体は生成し直しません。

## 全組み合わせと文章管理

6遺伝子だけでは各種 `3^6 = 729` 通り。現在のエネルギー状態も含む完全キーは `種|温度適性|速度|繁殖の重み|代謝|川|山|充足率` です。
各種 `3^7 = 2,187`、両種で **4,374通り**を扱います。

`data/status_explanations.json` の `stats` の順番がキーの順番です。

- `special`：種を含む完全一致キーで専用の冒頭文を追加。
- `relations`：複数能力の組み合わせに対する説明。速度×代謝、川×山、繁殖の重み×充足率、速度×温度適性の各9条件と、種別の条件を用意。
- `descriptions`：組み合わせルールで説明されなかった能力のフォールバック。
- `strengths` / `weaknesses`：各分類に対応する長所・注意点。
- `context`：現在気温・実際の消費と種別固有の捕魚条件。

ルールでカバーされた能力の単独説明は重ねず、同一文も重複させません。未知の遺伝子は効果を推測せず未分類として示します。新しい遺伝子を追加する場合は `stats` に名前・閾値・3段階分の文章を追加すると分類とフォールバックに入り、必要な組み合わせルールを追加できます。完全一致キーの長さが変わるため、既存の `special` は更新または削除してください。未定義のキー・種・分類を参照するJSONルールは読込時にエラーにします。

全件のCSV（UTF-8 BOM付き）は次で再生成できます。親ディレクトリは事前に作成してください。

```bash
python status_explainer.py --export /tmp/status_combinations.csv
```

`docs/status_combinations.zip` に4,374件の最終解説・分類・長所・短所を入れたCSVを収録しています。数値例は各分類区間の中点です。現在地や気温、正確な数値に依存する追加説明は実画面で算出され、分類一覧とは区別されます。

## ファイルと接続点

- `status_explainer.py`：分類、読取専用の解析、文章生成、全件CSV出力。外部サービス・Pygameに依存しません。
- `data/status_explanations.json`：閾値・文章・専用文・組み合わせルール。
- `status_panel.py`：日本語フォント、折り返し、スクロール、閉じる・E操作。個体・気温等の値が変われば再判定。
- `main.py`：可視化関数での初期化、イベント委譲、描画の3接続点と既存詳細のEキー案内だけ。
- `tests/test_status_explainer.py` / `tests/test_status_panel.py`：全件・境界値・無副作用・実イベントの検証。

`world.py` / `organism.py` / `config.py` / `experiment.py` / `pixel_art.py` は変更していません。既存選択画面の裏側にある描画やゲーム計算もそのままです。

```bash
python -m unittest discover -s tests -v
```

```bash
STATUS_SCREENSHOT_DIR=/tmp/status-screenshots python -m unittest discover -s tests -p 'test_status_panel.py' -v
```
